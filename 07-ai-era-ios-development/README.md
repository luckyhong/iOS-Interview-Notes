# AI 时代的 iOS 开发

2023 年之后，"AI 编程"从概念快速变成了 iOS 面试的常规环节。这不是要取代前面几个模块的 Runtime、RunLoop、内存管理、多线程这些"八股文"——那些依然是考察工程功底的地基，只是面试官现在会追加一层新的考察维度：**你是不是一个知道怎么和 AI 协作、也知道怎么把 AI 能力做进 App 里的 iOS 工程师**。

这个模块按照面试里被问到的先后顺序和频率，拆成四类问题：

| 分类 | 关注点 | 面试官想看什么 |
| --- | --- | --- |
| [01·AI 编程工具与研发效率](01-ai-coding-tools-and-productivity.md) | Cursor / Xcode Predictive Code / Claude Code / Copilot 怎么用、AI 生成代码的坑 | 你是否理性、高效地使用工具，而不是盲目依赖 |
| [02·苹果端侧 AI 技术栈](02-apple-on-device-ai-stack.md) | Core ML、Apple Intelligence、Foundation Models framework、Neural Engine | 你对苹果自家 AI 生态的了解深度 |
| [03·大模型能力集成到 iOS App](03-llm-integration-in-ios-apps.md) | 流式响应、上下文管理、多模态输入、安全性 | 你能不能把 AI 特性真正落地成可用的产品功能 |
| [04·职业发展与面试软实力](04-career-and-interview-soft-skills.md) | "AI 会不会取代 iOS 开发"、简历怎么写、传统八股是否还重要 | 你对行业变化的判断力和表达能力 |

## 怎么用这个模块

- 如果你是**准备面试的人**：建议先看 04，想清楚自己的立场和真实经历，再看 01-03 补技术细节——软实力问题往往在面试的第一轮就出现，是"过滤性"问题。
- 如果你是**面试官**：01-03 的问题都可以顺着候选人的实际项目经验继续追问，比空聊"你怎么看 AI"更能看出真实水平。
- 每道题都遵循这个仓库一贯的格式：先给一段可以直接背下来的**要点**，再给**为什么**，重要的会附一段可运行的示例代码。答案是一种思路参考，不是标准答案，欢迎提 PR 补充或指正。

## 一句话共识（写在前面，避免歧义）

AI 不会让"会写代码"这件事贬值到零，但它确实让"只会写代码、不会判断代码对不对"这件事迅速贬值。招聘一个 iOS 工程师，考察重点正在从"你记不记得这个 API"往"你能不能对 AI 给你的方案做出正确判断"迁移——这也是本模块所有题目背后的同一条线索。
